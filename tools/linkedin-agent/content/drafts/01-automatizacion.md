# Borrador 01 — Automatización

Automatizar no siempre significa agregar otra herramienta.

A veces el mejor cambio es eliminar un paso que nadie necesitaba.

Cuando evalúo un proceso de desarrollo, intento responder tres preguntas:

1. ¿Qué tarea se repite y con qué frecuencia?
2. ¿Qué podría fallar si se ejecuta sin supervisión?
3. ¿Cómo compruebo que el resultado es correcto?

Con esas respuestas es más fácil decidir si conviene usar un script, un pipeline de CI/CD o simplemente mejorar la documentación.

Una automatización útil debería ahorrar trabajo sin esconder errores.

En proyectos con Python, Git y aplicaciones web, prefiero empezar por procesos pequeños, verificables y fáciles de mantener.

¿Qué parte del desarrollo automatizarías primero en un proyecto nuevo?
